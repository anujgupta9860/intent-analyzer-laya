# Train & Deploy the Intent Analyzer Locally

End-to-end guide for training all five per-agent intent analyzers on your own
machine and serving them via the FastAPI service. Includes a **BERT fallback**
path for when the default encoder weights can't be downloaded.

## 1. What you're building

Each analyzer is a multi-task encoder (one shared transformer + a choice head
+ one Noul head per question), trained per agent:

| Agent     | Choice question  | Noul questions |
|-----------|------------------|----------------|
| billing   | billing_action   | 4              |
| orders    | order_action     | 4              |
| support   | support_topic    | 4              |
| account   | account_action   | 4              |
| sales     | sales_intent     | 4              |

The question specs are the single source of truth
(`src/analyzer_questions.py`). Training data is synthetic, generated by
`train/build_dataset.py`.

**Model tracks:**

| Track | `--model` value | When to use |
|-------|-----------------|-------------|
| Default (ModernBERT) | `model-hub/ModernBERT-base` (local copy) or `answerdotai/ModernBERT-base` | Normal path — best accuracy (0.95–1.00 val) |
| Fallback (BERT) | `bert-base-uncased` | §7 — when ModernBERT weights are blocked/unavailable |

The serving code (`src/analyzer_model.py`, `src/analyzers.py`) is
encoder-agnostic — it builds from `AutoModel`/`AutoConfig`, so a BERT-trained
checkpoint loads and serves with zero code changes.

## 2. Prerequisites

- Python 3.10+ (3.12 used here)
- ~4 GB free disk per agent for training (checkpoints), ~600 MB per agent for
  the final serving files
- CPU is fine (each agent trains in ~5–10 min on CPU); a GPU is faster
- `pip install -r requirements.txt`

```bash
cd ~/workspace/intent-analyzer-laya   # or wherever you cloned it
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

## 3. Get the encoder weights

`train/finetune.py` defaults to a **local copy** at `model-hub/ModernBERT-base`
because the HuggingFace `hub` client breaks behind some egress proxies.

**Path A — local copy already present** (this repo): do nothing, the default
`--model` just works.

**Path B — direct hub access** (your laptop, no proxy):

```bash
python train/finetune.py --agent billing \
    --model answerdotai/ModernBERT-base \
    --data train/data/billing.jsonl --out models/billing
```

**Path C — hub client blocked, but curl works** (fetch weights manually):

```bash
mkdir -p model-hub/ModernBERT-base && cd model-hub/ModernBERT-base
BASE=https://huggingface.co/answerdotai/ModernBERT-base/resolve/main
for f in config.json tokenizer.json tokenizer_config.json \
         model.safetensors; do
  curl -L -o "$f" "$BASE/$f"
done
cd ../..
```

If **all three paths fail** for ModernBERT (blocked domain, no weights
anywhere) → use the BERT fallback in §7.

## 4. Train all five agents

Build datasets, then fine-tune each agent. ~30–50 min total on CPU.

```bash
source .venv/bin/activate

# 1. Build synthetic datasets (one JSONL per agent)
for agent in billing orders support account sales; do
  python train/build_dataset.py --agent "$agent" --out train/data
done

# 2. Fine-tune (uses model-hub/ModernBERT-base by default)
for agent in billing orders support account sales; do
  python train/finetune.py --agent "$agent" \
      --data "train/data/${agent}.jsonl" \
      --out "models/${agent}"
done
```

Useful flags on `finetune.py`:

| Flag | Default | Notes |
|------|---------|-------|
| `--model` | `model-hub/ModernBERT-base` | Path B/C or §7 fallback |
| `--epochs` | 5.0 | 3–5 is plenty; watch val accuracy |
| `--lr` | 2e-5 | Standard for encoder fine-tuning |
| `--batch` | 8 | Lower to 4 on low-RAM machines |
| `--seed` | 42 | Reproducibility |

Each run writes to `models/<agent>/`:

- `pytorch_model.bin` — fine-tuned weights (~600 MB)
- `config.json`, `tokenizer.json`, `tokenizer_config.json`
- `calibration.json` — fitted temperatures + label contract (choice labels,
  Noul question IDs, agent name). **The server refuses to load a checkpoint
  whose labels don't match `src/analyzer_questions.py` exactly** — this is the
  guard against silent label-order mismatches.

Expected validation accuracy: **0.95–1.00** on choice, **0.95–1.00** on Noul
(see SDR §8 for the reference numbers).

## 5. Serve locally

```bash
source .venv/bin/activate
ANALYZER_CHECKPOINT_DIR=models \
ANALYZER_CONFIDENCE_THRESHOLD=0.6 \
  uvicorn src.app:app --host 0.0.0.0 --port 8081
```

Env vars (`src/config.py`):

| Var | Default | Meaning |
|-----|---------|---------|
| `ANALYZER_CHECKPOINT_DIR` | `models` | Parent dir containing one subdir per agent |
| `ANALYZER_CONFIDENCE_THRESHOLD` | `0.6` | Below this → `needs_human=true` |
| `ANALYZER_AGENTS` | all five | Comma list to serve a subset |

Health check: `curl localhost:8081/health` → lists which agents have a valid
checkpoint. Models lazy-load on first request per agent (~seconds), then stay
in memory.

## 6. Test it

Contract tests (no server needed — validates serving questions match training):

```bash
python -m pytest tests/ -q
```

All five agents via the API:

```bash
BASE=localhost:8081
for agent in billing orders support account sales; do
  echo "=== $agent ==="
  curl -s -X POST $BASE/analyze -H 'content-type: application/json' \
    -d "{\"query\": \"test query\", \"worker_agent\": \"$agent\"}" \
    | python3 -c "import json,sys; d=json.load(sys.stdin); \
        print(d['choice'], d['choice_confidence'], 'human:', d['needs_human'])"
done
```

Realistic per-agent queries (see README for the full set):

```bash
curl -s -X POST $BASE/analyze -H 'content-type: application/json' \
  -d '{"query": "delete my account immediately", "worker_agent": "account"}' \
  | python3 -m json.tool
# expect: delete_account @ ~1.0, is_irreversible=1.0
```

## 7. Fallback: train on BERT when ModernBERT is blocked

**When to use this:** the ModernBERT weights can't be obtained by any path in
§3 (hub domain blocked, no local copy, curl fails). BERT
(`bert-base-uncased`) is the most universally available encoder — it's
mirrored everywhere and almost never blocked.

**What changes:** one flag. Everything else (dataset, heads, calibration,
serving, API) is identical because the architecture is encoder-agnostic.

```bash
source .venv/bin/activate

# If the HF hub client works for BERT (it usually does even when
# ModernBERT is blocked — different CDN path):
for agent in billing orders support account sales; do
  python train/build_dataset.py --agent "$agent" --out train/data
  python train/finetune.py --agent "$agent" \
      --model bert-base-uncased \
      --data "train/data/${agent}.jsonl" \
      --out "models/${agent}"
done
```

If the hub client is blocked for BERT too, fetch with curl (same pattern as
§3 Path C):

```bash
mkdir -p model-hub/bert-base-uncased && cd model-hub/bert-base-uncased
BASE=https://huggingface.co/bert-base-uncased/resolve/main
for f in config.json tokenizer.json tokenizer_config.json \
         pytorch_model.bin; do
  curl -L -o "$f" "$BASE/$f"
done
cd ../..
# then: --model model-hub/bert-base-uncased
```

**Expected differences vs ModernBERT:**

| Aspect | ModernBERT (default) | BERT fallback |
|--------|---------------------|---------------|
| Val accuracy (choice) | 0.95–1.00 | ~0.90–0.97 (slightly lower — smaller model, WordPiece vs modern tokenizer) |
| Checkpoint size | ~600 MB | ~440 MB |
| Inference speed (CPU) | ~200–400 ms | ~150–300 ms (slightly faster) |
| Max seq length used | 128 | 128 (same — we truncate) |

**Do not mix tracks in one deployment.** All five agents must be trained on
the *same* encoder — the serving registry doesn't care, but mixing makes
latency/accuracy unpredictable and complicates the label contract. If you
fall back to BERT, retrain all five on BERT.

**Serving a BERT checkpoint:** no changes. Point
`ANALYZER_CHECKPOINT_DIR` at the BERT-trained `models/` dir and start the
service exactly as in §5. The `calibration.json` contract check works the
same way.

## 8. Deploy with Docker

`Dockerfile` (create at repo root):

```dockerfile
FROM python:3.12-slim
WORKDIR /srv/app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY src/ ./src/
# bake trained checkpoints into the image, or mount at runtime
COPY models/ ./models/
ENV ANALYZER_CHECKPOINT_DIR=/srv/app/models
EXPOSE 8081
CMD ["uvicorn", "src.app:app", "--host", "0.0.0.0", "--port", "8081"]
```

Build & run:

```bash
docker build -t intent-analyzer:local .
docker run -p 8081:8081 intent-analyzer:local
# or mount checkpoints at runtime instead of baking:
docker run -p 8081:8081 -v "$PWD/models:/srv/app/models" intent-analyzer:local
```

For Cloud Run (GCP), use `entrypoint.py`, which downloads per-agent
checkpoints from GCS on container startup instead of baking them:

```bash
ANALYZER_CHECKPOINT_GCS=gs://<bucket>/intent-analyzer \
ANALYZER_CHECKPOINT_DIR=/srv/app/models \
  python entrypoint.py   # downloads, then execs uvicorn
```

Each agent's GCS prefix needs the five serving files:
`pytorch_model.bin`, `config.json`, `tokenizer.json`,
`tokenizer_config.json`, `calibration.json`.

## 9. Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| `AnalyzerError: checkpoint not found` | `models/<agent>/calibration.json` missing | Train that agent (§4) or check `ANALYZER_CHECKPOINT_DIR` |
| `checkpoint choice labels != spec` | Checkpoint trained against a different question spec | Retrain with the current `src/analyzer_questions.py`; never hand-edit labels |
| `huggingface_hub` network errors | Egress proxy blocks the HF client | §3 Path A or C (local copy / curl) |
| OOM during training | Batch too large for RAM | `--batch 4`, close other apps |
| Slow first request per agent | Lazy model load (~seconds, one-time) | Expected; subsequent requests are ms |
| `needs_human=true` on everything | Threshold too high or uncalibrated checkpoint | Check `calibration.json` exists; lower `ANALYZER_CONFIDENCE_THRESHOLD` only as a debug step |
